# 20260309 진행 보고서

## Braktooth KNOB Exploit 수정

`sudo bluekit -t 64:7B:CE:BD:A5:2B -e braktooth_knob`을 실행하면 `Toolkit error⚠️ | Error during extracting information from the regex` 오류가 지속적으로 발생했습니다. `sudo bin/bt_exploiter --host-port=/dev/ttyUSB1 --target=64:7B:CE:BD:A5:2B --exploit=knob`으로 수동 실행한 결과, 기기가 취약한 것으로 확인되었으며 (`[Modules] KNOB Detected!!! Device vulnerable`), 이는 exploit 자체가 아닌 BlueToolkit의 exploit 출력 처리 방식에 문제가 있음을 의미했습니다. 이 문제는 특정 기기에 국한되지 않았으며 모든 대상 기기에서 동일하게 발생했습니다.

### 근본 원인 분석

세 가지 문제가 확인되었습니다:

1. **출력 wrapper 부재**: BlueToolkit engine은 모든 PoC type exploit이 `BLUEEXPLOITER DATA: code=X, data=...` 형식의 구조화된 출력을 생성할 것으로 예상합니다 (`bluekit/bluekit/constants.py`에 정의됨). 정상 작동하는 PoC exploit(예: `custom_nino_check`)은 `bluekit.report`의 `report_vulnerable()` / `report_not_vulnerable()`를 호출하는 Python wrapper를 사용하여 해당 출력을 생성합니다. 그러나 `braktooth_knob.yaml`은 `bt_exploiter` 바이너리를 직접 호출하고 있었으며, 해당 바이너리는 `[Modules] KNOB Detected!!!`를 출력하는데 이는 engine의 regex가 파싱할 수 없는 형식입니다.

2. **wrapper script의 버그**: `modules/tools/custom_exploits/`에 `bluekit_knob.py` wrapper script이 이미 존재했으나, 여러 버그로 인해 정상 작동하지 않았습니다: 오타 (`proc.waite()` → 올바른 형태는 `proc.communicate()`), 미정의 변수 (`data` → 올바른 형태는 `output`), `import re` 누락, 잘못된 regex 패턴 (`KNOB is detected` → 실제 출력은 `KNOB Detected`), `__main__`에서의 함수명 불일치 (`check_CVE_2018` → 올바른 형태는 `check_for_CVE_2018`), 그리고 탐지 성공 시 `report_vulnerable()` 호출 누락이 있었습니다.

3. **프로세스 미종료**: KNOB 탐지 후 `bt_exploiter`는 무한 retry/reconnection 루프에 진입하여 종료되지 않습니다. `proc.communicate()`는 프로세스 종료를 대기하므로, timeout 값과 관계없이 항상 시간 초과가 발생했습니다.

### 변경 사항

#### `bluekit/exploits/braktooth_knob.yaml`

- `command`를 `./bin/bt_exploiter --host-port=/dev/ttyUSB1 --exploit=knob --random_bdaddress`에서 `python3 bluekit_knob.py`로 변경하여, wrapper script을 통해 실행되도록 했습니다
- `directory.directory`를 `modules/tools/braktooth/wdissector`에서 `modules/tools/custom_exploits`로 변경하여, 런타임에 wrapper script을 찾을 수 있도록 했습니다
- `parameter_connector`를 `=`에서 `" "`로 변경하여, wrapper의 argparse 방식 인자 형식에 맞추었습니다 (`--target=64:7B:CE:BD:A5:2B` 대신 `--target 64:7B:CE:BD:A5:2B`)
- `max_timeout: 120`을 추가하여 engine이 exploit 완료까지 충분한 시간을 확보하도록 했습니다

#### `modules/tools/custom_exploits/bluekit_knob.py`

- 누락된 `import re`를 추가했습니다
- `proc.waite()` 오타를 `proc.communicate()`로 수정했습니다
- 미정의 변수 `data`를 `output`으로 수정했습니다
- regex를 `b'KNOB is detected'`에서 `b'KNOB Detected'`로 수정하여 실제 `bt_exploiter` 출력과 일치시켰습니다
- `report_vulnerable()`와 `report_not_vulnerable()` 호출을 추가하여 engine이 요구하는 `BLUEEXPLOITER DATA:` 출력을 생성하도록 했습니다
- `__main__`의 함수 호출을 `check_CVE_2018`에서 `check_for_CVE_2018`로 수정했습니다
- `bt_exploiter` 바이너리에 절대 경로를 사용하고, `subprocess.Popen`에 `cwd` 매개변수를 추가하여 braktooth가 자체 디렉토리에서 실행되도록 했습니다
- `directory` 매개변수에 기본값 `''`을 설정하여, 해당 인자 없이 호출 시 `TypeError` 발생을 방지했습니다
- `proc.communicate(timeout=90)`을 행 단위 stdout 읽기로 교체했습니다. 이것이 가장 핵심적인 수정 사항이었습니다: `bt_exploiter`는 KNOB 탐지 후 retry 루프에 진입하여 종료되지 않으므로, `communicate()`는 항상 시간 초과가 발생했습니다. 새로운 방식은 출력을 점진적으로 읽으며 `KNOB Detected` 패턴을 즉시 감지하고, `report_vulnerable()`를 호출한 후 프로세스를 종료합니다
