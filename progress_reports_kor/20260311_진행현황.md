# 20260311 진행 보고서

## recon Exploit 수정 (SC) 및 커스텀 Exploit 수정 (NiNo, Legacy Pairing)

대상 기기 `64:7b:ce:bd:a5:2b`에 대해 실행 시 3개의 exploit이 `Toolkit error⚠️`로 실패했습니다: `reconnaissance_SC_supported`, `custom_nino_check`, `custom_legacy_pairing_second_check`. 각각 서로 다른 근본 원인을 가지고 있었습니다.

### 근본 원인 분석

#### 1. `reconnaissance_SC_supported` — recon 데이터 구조의 KeyError

`python3 bluekit_recon_based_check.py --case 1 --target 64:7b:ce:bd:a5:2b`를 직접 실행한 결과, `bluekit_recon_based_check.py`의 55번째 줄에서 `KeyError: 'sc'`가 발생했습니다. 코드에서 `features["sc"]`에 접근하고 있었으나, `pybtool` 기반으로 재작성된 `Recon` 클래스가 생성하는 새로운 recon 데이터 형식에서는 `sc`가 `pairing_features` 내부에 중첩되어 있었습니다:

```json
{
    "pairing_features": {
        "sc": true,
        "io_capabilities": "DisplayYesNo"
    }
}
```

기존 recon 시스템에서는 `sc`를 최상위 레벨에 저장했으나, 새 시스템에서는 그렇지 않습니다.

#### 2. `custom_nino_check` — stdout 오염으로 인한 engine 출력 파싱 실패

BlueToolkit engine은 exploit의 stdout을 캡처하여 `ast.literal_eval`로 파싱하며, `bluekit.report`의 `report_vulnerable()` / `report_not_vulnerable()` / `report_error()`가 생성하는 `{'return_code': X, 'return_data': '...'}` 형태의 dict를 기대합니다. `bluekit_nino_check.py` 스크립트에는 두 가지 문제가 있었습니다:

- **자식 프로세스의 `sudo`**: 11번째 줄에서 `HCITOOL_INFO = "sudo hcitool info {target}"`로 정의되어 있었습니다. bluekit이 `sudo`로 실행될 때, `pexpect`가 생성하는 자식 셸은 sudo 세션을 상속받지 못하여 비밀번호 프롬프트 timeout이 발생했습니다. 이로 인해 `report_error()`가 호출되었으나, 두 번째 문제로 인해 이미 피해가 발생한 상태였습니다.

- **stdout 오염**: 스크립트가 최종 `report_*()` 호출 전에 디버그 출력용 `print()`를 사용하고 있었습니다 (`print(INSTRUCTIONS)`, `print("Remove: ...")`, `print("Hcitool info: done")`, `print("Pair output: ...")`, `print("Connect output: ...")`). engine은 이 모든 텍스트가 혼합된 stdout을 수신하였고, dict가 아닌 텍스트에 대해 `ast.literal_eval`이 실패했으며, `engine.py`의 `process_custom_output()`에서 기본 분기로 빠졌습니다 (exploit 이름에 "braktooth"가 포함되어 있지 않으므로). 결과적으로 `UNKNOWN_STATE`가 반환되었습니다.

#### 3. `custom_legacy_pairing_second_check` — `get_hcidump` 메서드 누락

스크립트가 13번째 줄에서 `recon.get_hcidump(target=target)`를 호출하고 있었으나, `pybtool`을 사용하도록 재작성된 새 `Recon` 클래스에는 기존 recon 구현에 존재하던 `start_hcidump`, `stop_hcidump`, `get_hcidump` 메서드가 포함되어 있지 않았습니다. 이로 인해 `AttributeError: 'Recon' object has no attribute 'get_hcidump'`가 발생했습니다.

### 변경 사항

#### `modules/tools/custom_exploits/bluekit_recon_based_check.py`

- 새로운 recon 데이터 구조에 맞추어 55번째 줄의 `features["sc"]`를 `features["pairing_features"]["sc"]`로 변경했습니다

#### `modules/tools/custom_exploits/bluekit_nino_check.py`

- `HCITOOL_INFO` 명령에서 `sudo`를 제거했습니다: `"sudo hcitool info {target}"`를 `"hcitool info {target}"`로 변경 (11번째 줄), bluekit이 이미 `sudo`로 실행되기 때문입니다
- 모든 디버그 `print()` 호출을 `logging.info()`로 변경하여 (53, 58, 63, 76, 111번째 줄), `report_*()` dict 출력만 stdout으로 전달되도록 했습니다

#### `bluekit/bluekit/recon.py` (`~/BlueToolkit/bluekit/` 내)

- 모듈 import에 `import signal`과 `import subprocess`를 추가했습니다
- 기존 recon 구현에서 포팅한 세 가지 메서드를 `Recon` 클래스에 추가했습니다:
  - `start_hcidump(self)` — `hcidump -X`를 서브프로세스로 생성합니다
  - `stop_hcidump(self, process)` — hcidump 프로세스에 SIGINT를 전송하고 캡처된 출력을 반환합니다
  - `get_hcidump(self, target)` — hcidump를 시작하고, `check_device_status(target)`를 통해 연결을 트리거한 후, hcidump를 중지하고 출력 라인을 반환합니다

### 결과

모든 변경 사항을 적용한 후:

- `reconnaissance_SC_supported`가 `{"code": 1, "data": "Secure Connections supported"}`를 올바르게 보고합니다
- `custom_nino_check`와 `custom_legacy_pairing_second_check` 수정 사항이 적용되었으며, Galaxy Note10+ 5G에서 테스트가 성공했습니다.
