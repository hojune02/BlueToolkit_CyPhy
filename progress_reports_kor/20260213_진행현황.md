# 20260213 진행현황

## 이전까지의 현황

iPhone을 제외한 스피커 기기와 삼성 휴대폰 기기에 대해 `custom_nino_check`을 실행하는데에 성공했습니다.

오늘 주요 진척 사항으로는:
- `custom_nino_check`를 iPhone 13 Pro 대상으로 실행하는데 성공했습니다.
- `bluing` 의존성 때문에 실행하지 못했던 다음 세 가지 취약점을 실행하는데 성공했습니다.
    - reconnaissance_SC_supported
    - reconnaissance_SSP_supported 
    - reconnaissance_possible_BLUR

## custom_nino_check - iPhone 13 Pro 대상 취약점 확인 성공

원래 custom_nino_check 내부의 동작은 `reconnect.sh` 내부의 다음 커맨드들을 순서대로 실행하는 것이었습니다:

```bash
bt-agent -c NoInputNoOutput
bluetoothctl remove {target}
sudo hcitool scan
sudo hcitool info {target}
bluetoothctl pair {target}
bluetoothctl connect {target} # 이게 성공하면 Vulnerable
bluetoothctl remove {target}
```

이때 두번째 단계인 `bluetoothctl remove {target}`을 제거했는데, 그 이후 더 이상 아이폰 대상 `custom_nino_check`에만 존재했던 regex parsing error가 나오지 않았고, 정상적으로 아이폰 화면에서도 페어링 요청이 뜨면서 취약점이 존재함을 확인했습니다. 이때 아이폰에서는 BlueToolkit을 실행하는 노트북을 잊은 뒤 `custom_nino_check`를 실행해야 합니다. 그렇지 않으면 다시 regex parsing error가 발생하는 것을 확인했습니다.

## bluing 의존성 대체: btmon

`reconnaissance` 관련 세 가지 취약점은 타켓 리모트 기기의 LMP (Link Manager Protocol) 정보를 요구했습니다. 이때 BlueToolkit이 알아야하는 LMP 정보는 Secure Simple Pairing, Secure Connections 등의 기기 정보를 말합니다. BlueToolkit은 `bluing`을 통해 이 정보를 획득하여 파싱한 뒤 취약점 분석에 사용하는 것을 확인했습니다. 따라서 `bluing` 이외의 CLI 커맨드 중 LMP 정보를 얻을 수 있는 커맨드를 찾아 `bluing`을 대체하고자 했고, `btmon`을 찾을 수 있었습니다.

`/usr/share/BlueToolkit` 내부에 `btmon_feature_extractor.py`를 생성하여 `btmon`으로부터 얻은 LMP 정보를 `bluing`의 출력 형식에 맞게 저장하는 역할을 합니다. 이 프로그램은 타켓 기기의 `bluing_lmp.log`가 존재하지 않을때만 실행됩니다. 즉 타겟 기기를 대상으로 처음 BlueToolkit을 실행할 때에만 `btmon_feature_extractor.py`가 작동합니다.

`btmon_feature_extractor.py`는 다음과 같은 순서로 작동합니다:

- `btmon`을 실행하여 주변 블루투스 정보를 수집한다.
- 얻은 정보 중 타겟 기기의 MAC 주소를 가지고 있는 로그만 따로 빼낸다.
- 얻은 로그를 분석하여 만약 그 안에 아래 정보가 모두 포함되어 있다면 실행을 종료하고 결과를 `/usr/share/BlueToolkit/data/tests/{target_mac}/bluing_lmp.log`에 저장한다.
    - LE Supported (Controller)
    - LE Supported (Host)
    - Simultaneous LE and BR/EDR to Same Device Capable (Controller)
    - Simultaneous LE and BR/EDR to Same Device Capable (Host)
    - Secure Simple Pairing (Controller Support)
    - Secure Simple Pairing (Host Support)
    - Secure Connections (Controller Support)
    - Secure Connections (Host Support)
- 정보가 모두 들어있지 않다면 다시 `btmon`을 실행하여 동작을 반복한다.

이렇게 필요한 정보가 모두 타겟 기기의 `bluing_lmp.log`에 저장되면 `reconnaissance` 관련 취약점이 정상적으로 작동하는 것을 확인하였습니다.
