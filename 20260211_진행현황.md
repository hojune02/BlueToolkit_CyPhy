# 20260211 진행현황

## 이전까지의 현황

BlueToolkit 자체의 실행은 파이썬 버전을 3.10으로 낮추고 `setuptools`의 버전을 낮추어 다시 다운받는 방법을 통해 해결했습니다:
```bash
(.venv) (base) cyphy@cyphy-Lenovo-V15:~$ sudo bluekit -h
usage: bluekit [-h] [-t TARGET] [-l] [-c] [-ct] [-ch] [-v VERBOSITY] [-ex EXCLUDEEXPLOITS [EXCLUDEEXPLOITS ...]]
               [-e EXPLOITS [EXPLOITS ...]] [-r] [-re] [-rej] [-hh HARDWARE [HARDWARE ...]]
               ...

positional arguments:
  rest

options:
  -h, --help            show this help message and exit
  -t TARGET, --target TARGET
                        target MAC address
...
```
그러나 공격을 진행하려고 하면 타겟 기기와의 연결이 계속해서 끊기는 문제가 있었습니다. 이를 오늘 해결하였고, 해결 과정을 기록하고자 본 파일을 만들었습니다.

## 문제 해결

### 1. `bluekit` 내부 `reconnect.sh`상의 문제점

`bluekit`은 BlueToolkit이 사용하는 CLI 도구입니다. 기기와의 연결을 담당하는 `reconnect.sh` 파일이 존재하는데, 깃헙에 존재하는 원본 파일은 다음과 같습니다:

```sh
#!/bin/bash

mac=$1 # DEH-4400BT
...
rfkill unblock bluetooth

bluetoothctl -- power on
bluetoothctl -- discoverable on
bluetoothctl -- pairable on
bluetoothctl -- agent NoInputNoOutput    # if you delete this part it will pair as normal, one would need to accept pairing only on the device (test)
bluetoothctl -- default-agent
bluetoothctl -- remove $mac
sudo hcitool info $mac
bluetoothctl -- trust $mac
bluetoothctl -- connect $mac
bluetoothctl -- remove $mac
bluetoothctl -- disconnect
...
```

이 파일이 기기 연결이 계속해서 끊기는 문제의 주된 원인이었습니다. 문제가 발생한 지점으로는:

- bluetoothctl의 agent가 NoInputNoOutput으로 되어있는데, 몇몇 기기는 블루투스 연결을 하고자 하는 기기가 NoInputNoOutput이면 연결을 거부하는 행동을 보입니다.
- `bluetoothctl --`의 커맨드를 연달아 사용하는데, 이는 fire-and-forget 방식으로 이때 `connect`와 `remove`간의 race condition이 발생할 수 있습니다. 연결이 되고 난 뒤 연결 상태를 확인할 새도 없이 바로 연결이 해제되는 경우입니다.

따라서 `/usr/share/BlueToolkit/bluekit/bluekit/reconnect.sh`를 아래와 같이 수정하였고, 그 이후 연결상태를 확인하는 커맨드인 `sudo -E PATH=$PATH bluekit -t AA:BB:CC:DD:EE:FF -ct`가 잘 작동하였습니다:

```sh
#!/bin/bash
mac=$1

rfkill unblock bluetooth

# Use a single bluetoothctl session with heredoc
bluetoothctl <<EOF
power on
discoverable on
pairable on
agent on
default-agent
disconnect $mac
remove $mac
trust $mac
connect $mac
EOF

# Wait for connection to establish
sleep 5

# Clean up
bluetoothctl <<EOF
disconnect $mac
EOF

...

```

### 2. `hcitool info` 커맨드의 문제점

연결 문제를 해결하고 난 뒤, 익스플로잇을 지정해 공격하려 하면 아래와 같은 에러가 지속적으로 발생하였습니다.

```bash
(.venv) (base) cyphy@cyphy-Lenovo-V15:~$ sudo -E env PATH=$PATH bluekit -t F4:2B:7D:2F:3E:5B -e bleedingtooth_badchoice bleedingtooth_badkarma bleedingtooth_badvibes blueborne_CVE_2017_0785 blueborne_CVE_2017_1000250 blueborne_CVE_2017_1000251 custom_insecure_numeric_comparison_implementation custom_legacy_pairing_second_check custom_method_confusion_check custom_nino_check
/usr/share/BlueToolkit/data/tests/F4:2B:7D:2F:3E:5B/recon/hciinfo.log
Traceback (most recent call last):
  ...
  File "/usr/share/BlueToolkit/.venv/lib/python3.12/site-packages/bluekit/recon.py", line 82, in determine_bluetooth_version
    output = mm.search(text).group()
             ^^^^^^^^^^^^^^^^^^^^^
AttributeError: 'NoneType' object has no attribute 'group'
```

연결된 기기(이 경우 F4:2B:7D:2F:3E:5B)에 대한 `hciinfo.log`를 먼저 읽는데, 이때 NoneType 데이터가 읽혀 에러가 발생했습니다.

bluekit이 기기와 연결되고 난 후 `hcitool info`를 실행하여 연결 기기의 LMP 버전을 확인해야 하는데, 이때 커맨드 실행값이 실행할 때마다 이 정보를 포함하기도 하고, 포함하지 않기도 합니다. 아래의 예시에서 같은 커맨드가 다른 결과를 보여준다는 것을 확인할 수 있습니다:

```bash
(base) cyphy@cyphy-Lenovo-V15:~$ sudo hcitool info F4:2B:7D:2F:3E:5B
Requesting information ...
	BD Address:  F4:2B:7D:2F:3E:5B
	OUI Company: Chipsguide technology CO.,LTD. (F4-2B-7D)
	Features: 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x00
		
(base) cyphy@cyphy-Lenovo-V15:~$ sudo hcitool info F4:2B:7D:2F:3E:5B
Requesting information ...
	BD Address:  F4:2B:7D:2F:3E:5B
	OUI Company: Chipsguide technology CO.,LTD. (F4-2B-7D)
	Features: 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x00
		
(base) cyphy@cyphy-Lenovo-V15:~$ sudo hcitool info F4:2B:7D:2F:3E:5B
Requesting information ...
	BD Address:  F4:2B:7D:2F:3E:5B
	OUI Company: Chipsguide technology CO.,LTD. (F4-2B-7D)
	LMP Version: 5.3 (0xc) LMP Subversion: 0x682
	Manufacturer: Actions (Zhuhai) Technology Co., Limited (992)
	Features page 0: 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x00
```

`hcitool info`를 실행했을 때의 출력을 그대로 해당 기기의 `hciinfo.log`에 저장하기 때문에, 일단 문제를 지금 해결하기 위해서 수동으로 LMP 버전 정보가 나올 때까지 `hcitool info` 커맨드를 실행하고 그 결과를 직접 복사해 붙여넣는 방식으로 해결했습니다. 

또한 bluekit 내부에 위치한 `recon.py`의 `run_recon` 함수를 수정하여, `hcitool info`의 결과에 LMP 버전 정보가 포함될 때까지 최대 5번 커맨드를 실행하게끔 변경하였습니다.

### 수정사항 요약

- `reconnect.sh`에서 사용한 `bluetoothctl`의 `agent`를 `NoInputNoOutput`에서 `on`으로 변경. 또한 `bluetoothctl connect`와 `bluetoothctl remove`간의 race condition을 해결 -> 연결 상태가 거부되지 않고, 또 유지됨.
- 타겟 기기의 `hciinfo.log`에 LMP 버전 정보가 포함되지 않아 공격이 실행되지 않음. `hcitool info` 커맨드를 직접 실행하여 LMP 버전이 포함된 출력을 수동으로 복사 및 붙여넣기하여 해결.
- `run_recon` 함수를 변경하여 LMP 버전 정보가 포함될 때까지 최대 5번 커맨드를 실행하도록 변경.
